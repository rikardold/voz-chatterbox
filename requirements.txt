# ⚠️ LEIA ANTES DE MEXER: por que `--no-deps` no chatterbox
#
# O `chatterbox-tts` 0.1.7 declara:
#
#     torch==2.6.0   ; python_version < "3.14"
#     torch>=2.9.0   ; python_version >= "3.14"
#
# O pin do 2.6 vale para as imagens oficiais (Python 3.11/3.12). E o torch 2.6 **não tem kernel
# para sm_120** — a GPU Blackwell que o Runpod passou a alocar em 19/10/2026. O worker morria no boot:
#
#     NVIDIA RTX PRO 6000 Blackwell ... capability sm_120 is not compatible
#     RuntimeError: CUDA initialization failed: no kernel image is available
#     Worker is unhealthy, exiting.
#
# Instalar o pacote normalmente força o downgrade do torch e desfaz a correção em silêncio. Fixar
# `torch==2.8` via constraint (a primeira tentativa) torna a resolução IMPOSSÍVEL — o pip recusa com
# `ResolutionImpossible`, e está certo: o pin do pacote e a constraint não podem coexistir.
#
# A saída é instalar `chatterbox-tts --no-deps` e listar AQUI as dependências que ele realmente usa.
# O torch fica sendo o da IMAGEM BASE (2.8 + CUDA 12.8, que compila para sm_120 e mantém sm_50..sm_90
# — as GPUs antigas continuam servidas). O pacote não usa nada exclusivo do 2.6: o pin é
# conservadorismo do autor, e o CI confere que o import do Llama e a síntese continuam funcionando.
#
# Se o `chatterbox-tts` subir de versão, confira a lista abaixo contra `requires_dist` do PyPI.
####
