# O que o pip NÃO pode mexer nesta imagem.
#
# ## Por que este arquivo existe
#
# O `chatterbox-tts` declara `torch==2.6.0`. A imagem base é `pytorch/pytorch:2.8.0-cuda12.8` porque o
# Runpod passou a alocar GPU Blackwell (`sm_120`), e o torch 2.6 não tem kernels para ela — o worker
# morria no boot com "no kernel image is available for execution on the device".
#
# Sem esta constraint, o `pip install` veria o conflito e REBAIXARIA o torch para 2.6.0, desfazendo a
# correção em silêncio: o build passaria, e o worker voltaria a morrer na GPU.
#
# `==2.8.0` casa com o que a imagem base já traz. Se um dia a base mudar de versão, este número muda
# junto — e o build falha se não mudar, que é o comportamento desejado: melhor vermelho no CI do que
# worker morto em produção.
#
# ## Por que só torch e torchaudio estão aqui
#
# O `torchvision` NÃO vem na variante `runtime` da imagem base: quem o traz é o `chatterbox-tts`. Se
# ele fosse fixado aqui e o par estivesse errado, o build quebraria por um número que eu escolhi — e a
# mensagem apontaria para o lugar errado (foi a primeira falha deste worker: `torchvision 0.20.1+cu124
# requires torch==2.5.1, but you have torch 2.6.0`). Deixando-o livre, o pip resolve a versão casada
# com o torch que esta constraint protege.
#
# torch e torchaudio são um par fixo do fornecedor: o torchaudio é compilado contra a versão exata do
# torch, e um mismatch estoura no primeiro `import`.
torch==2.8.0
torchaudio==2.8.0
